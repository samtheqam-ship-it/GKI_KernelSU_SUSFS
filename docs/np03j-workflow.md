# مسار جهاز نوفا الخاص

هذا المسار يبني نواة واحدة للجهاز المحدد، ومدير صلاحيات مموّهًا بهوية ثابتة وتوقيع خاص. التشغيل يدوي فقط من [صفحة المسار](https://github.com/samtheqam-ship-it/GKI_KernelSU_SUSFS/actions/workflows/np03j-6.1-lts.yml). لا يحتاج اختيار الإعدادات عند كل تشغيل؛ ملف الإعدادات يثبت الاختيارات المتفق عليها.

```text
device = NP03J
device_kmi = 6.1-android14-11
release_type = Release
kernel_build_version = 6.1.x-android14
os_patch_level = lts
root_flavor = KernelSU-Next
page_size = 4k
commit_mode = latest
use_cache = false
allow_version_mismatch = false
brand_name = ""
keep_kmi = true
use_susfs = true
use_nomount = true
use_bbg = true
use_net = false
use_ds = false
use_ntsync = false
use_ptrace = false
use_unicode = false
use_bpf = false
use_perf = false
```

## تهيئة التوقيع مرة واحدة

اتصال المستودع المستخدم لإنشاء هذه الملفات لا يتيح كتابة أسرار المستودع. لذلك لم يُنشأ مفتاح توقيع داخل المستودع، ولم يُرفع مفتاح خاص أو كلمة مرور إلى الملفات العامة. يلزم تنفيذ التهيئة التالية قبل تشغيل البناء.

على الحاسوب الذي ستحتفظ فيه بنسخة المفتاح الأصلية، يلزم تثبيت أداة إدارة المستودعات وسجلّ مفاتيح جافا. يتعرف السكربت أيضًا على نسخة جافا المرفقة مع استوديو أندرويد في مساره المعتاد على ويندوز. بعد تسجيل الدخول إلى حسابك بأداة إدارة المستودعات، شغّل السكربت من مجلد المستودع:

```powershell
gh auth login
powershell -ExecutionPolicy Bypass -File .\tools\Setup-NP03JSigning.ps1
```

ينشئ السكربت مفتاحًا خاصًا وشهادة عامة، ويحتفظ بنسخة محلية يمكن إعادة استخدامها. ينقل بيانات المفتاح وكلمة مروره إلى أسرار المستودع المشفّرة عبر الإدخال القياسي، دون وضعهما ضمن أوامر العمليات أو ملفات المستودع. إعادة تشغيل السكربت تعيد استخدام النسخة المحلية الموجودة. لا تحذف هذه النسخة ولا تستبدلها بمفتاح جديد عند تحديث المدير.

```text
Local backup: %USERPROFILE%\NP03J-Signing-Backup
Key alias: np03j
Repository secret: NP03J_KEYSTORE_B64
Repository secret: NP03J_KEYSTORE_PASSWORD
```

إذا لم توجد الأسرار، يتوقف المسار في فحص المتطلبات قبل تنزيل مصادر النواة وبنائها. هذا شرط فعلي للتوقيع الثابت، وليس طلب موافقة جديدًا.

## ما يفعله التشغيل

يحل المسار أحدث رؤوس الفروع مرة واحدة في بداية التشغيل، ويحفظ معرفاتها الكاملة. تشمل هذه العملية ملفات بيان مصادر أندرويد ومشاريعه، ومصدر المدير الرسمي، ومصدر دمج الصلاحيات مع إخفاء الآثار، ومصدري تعريف تعديلات الملفات والحماية. تستخدم جميع المراحل هذه المعرفات نفسها حتى لو تغيرت الفروع أثناء البناء.

يأتي المدير من الفرع الرسمي الذي يستخدمه [مسار بناء المدير الرسمي](https://github.com/KernelSU-Next/KernelSU-Next/actions/workflows/build-manager-ci.yml). يُنفّذ منطق التمويه الرسمي مع هوية حزمة ثابتة، ثم يُبنى المدير ومكوّناه التنفيذيان من المصدر نفسه لمعمارية الجهاز. لا يُنزل ملف مدير جاهز من إصدار آخر. لا يشغّل هذا المسار مسار البناء الرسمي في المستودع الآخر، لأن ذلك لا يتيح استخدام هويتك وشهادتك الخاصتين داخل هذه الحزمة.

يأتي دمج إخفاء الآثار في النواة من الفرع الذي يعتمد عليه المشروع لهذا الغرض. يشترط المسار أن يحتوي هذا الفرع على التعديل الرسمي المحدد للمدير، وأن تتطابق شجرة واجهة الاتصال كاملة بين المصدرين. يرفض إكمال البناء إذا تخلف فرع الدمج عن المصدر الرسمي أو اختلفت الواجهة. لا يستبدل المصدر الأحدث تلقائيًا بمصدر أقدم لإجبار البناء على النجاح.

يُحسب رقم المدير من تاريخ المصدر الرسمي الكامل. تحمل النواة الرقم نفسه، وتثق في شهادة هذا المدير وهوية حزمتِه المحددتين. يتحقق المسار من توقيع التطبيق الفعلي قبل تمرير الشهادة إلى مرحلة النواة، ثم يتحقق من وجود بصمة الثقة في الصورة الناتجة.

يختار المسار أحدث الفرع طويل الدعم لأندرويد، ويحافظ على جيل واجهة وحدات النواة من المصدر. لا يعني ذلك تنزيل أحدث رقم من فرع لينكس الخام إذا لم يصل بعد إلى فرع أندرويد المحدد.

تُفعّل جميع خيارات إخفاء الآثار العشرة المتاحة في مصدر الدمج الحالي. تُفعّل حماية النطاق الأساسي ضمن قائمة وحدات الحماية النشطة، ويُبنى تعريف تعديلات الملفات داخل النواة. تُنتج له وحدة إدارة منفصلة من المعرف نفسه، بمثبت يتحقق من التعريف المدمج ولا يحمّل تعريفًا منفصلًا.

يفحص المسار الإعدادات الفعلية المتولدة من البناء، وحجم الصفحة في ترويسة الصورة، وجيل واجهة الوحدات في نص الإصدار. يحتفظ بالتنفيذ الأصلي لفحص إصدارات رموز الوحدات، ويقارن ملفه بالمصدر قبل البناء. يتحقق أيضًا من إدماج إعدادات النواة الأصلية المعروضة للتطبيقات؛ أما ملف الإعدادات المنشور للمراجعة فهو إعداد البناء الحقيقي.

لا تستعاد مخابئ بناء ولا تحفظ. لا تضيف هذه الإعدادات حزم الشبكات أو الحاويات أو المزامنة أو ترقيعات التتبع أو الترميز أو حزمة التتبع البرمجية أو حزمة الأداء. ما يكون موجودًا أصلًا في إعدادات أندرويد القياسية يبقى خاضعًا لمصدره.

## الناتج

بعد نجاح المراحل، يعيد المسار فحص تطابق الملفات وبصماتها قبل النشر. يقارن شهادة المدير وهويته بآخر إصدار خاص بهذا الجهاز ويرفض تغييرهما أو خفض رقم المدير. ينشئ إصدارًا مسودة أولًا، ويرفع جميع الملفات، ثم يجعله إصدارًا نهائيًا. لا يستبدل ملفات إصدار سابق.

تتضمن الحزمة نواة قابلة للتثبيت، والمدير الموقّع، ووحدة إدارة تعديلات الملفات، والشهادة العامة، وبيان المصادر، وإعداد البناء الحقيقي، وملفات المطابقة والبصمات. لا تتضمن المفتاح الخاص أو كلمة مروره. تُقيّد حزمة تثبيت النواة بطراز الجهاز أو أسماء منتجاته المحددة، وتتطلب عائلة النواة وحجم الصفحة المناسبين.

التحقق المحلي يشمل بنية المسار، واختبارات رفض المدخلات والملفات المتعارضة، وإعادة تطبيق الترقيعات على ملفات المصدر الحالية. نجاح البناء الكامل يُثبت عند تشغيل المسار. إقلاع الجهاز ونتائج كاشفات الصلاحيات لا تتحقق بها هذه الاختبارات ولا يقدّم المسار ضمانًا بشأنها.
